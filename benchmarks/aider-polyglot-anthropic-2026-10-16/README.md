# Aider Polyglot：Opus + Haiku 四种组合实测

2026 年 10 月 16 日。数据集为 Harbor Hub 的 `aider/aider-polyglot`（共 225 题）。用固定随机种子 20261016，每种语言抽 2 题，共 12 题，每题每组跑 1 次。模型通过 Claude Agent SDK 在本机运行，禁用全部内置工具，只开放一个在 Daytona 容器里执行的 `bash` 工具。不加载用户的 Claude 全局设置。测试代码对模型不可见，过程中也不向模型反馈任何评分结果。每次运行开始前删除 `/app/.oracle`（加密参考答案，默认密码是公开的）。

## 结果（有效 10 题）

两道 Java 题排除：评分脚本从 `services.gradle.org` 下载 Gradle 时连接被重置，代码根本没有被测试。

| 组别                      | 通过      | 平均花费 | 费用构成                                  |
| ------------------------- | --------- | -------: | ----------------------------------------- |
| Opus 5.5 单独做           | 9/10      |   $0.239 | 全部为 Opus                               |
| Haiku 5.5 单独做          | 7/10      |   $0.010 | 全部为 Haiku                              |
| Opus 写规格、Haiku 代笔   | **10/10** |   $0.247 | Opus $0.237 + Haiku $0.010                |
| Haiku + 原生 Opus advisor | 9/10      |   $0.221 | Opus $0.211（共 11 次求助）+ Haiku $0.010 |

逐题结果见 [stats.json](stats.json)。

## 分析

- **两种组合都把 Haiku 提到了 Opus 的正确率**：Haiku 单独做 7/10，加上 Opus 后是 9/10 或 10/10。"写规格、代笔"一题都没错，还做对了一道 Opus 单独做时做错的题（Python `tree-building`）。不过每组只有 10 题，差 1 题不能说明谁更强。
- **"写规格、代笔"没有省钱**：Opus 写方案的花费和它自己把题做完几乎一样。方案约 3200 到 4200 字符（约 2000 到 2600 输出 token），而 Opus 直接写代码的输出约 1500 到 1800 token，两者在同一量级。
- **花费主要来自固定上下文，不是输出**：Opus 每次会话都要带上约 3 万 token 的运行框架上下文。缓存没命中时，单次花费约 $0.29 到 $0.34；命中时约 $0.08 到 $0.09。输出部分只占一小块。这两档价格的差别取决于缓存是否命中，和哪种组织方式关系不大。
- **原生 advisor 单次求助约 $0.19**：每次都要读完整个对话（平均约 3.6 万 token），没有命中缓存。之所以整体最便宜，是因为每题只求助 1 到 2 次，Opus 不参与反复执行命令的循环。如果 Opus 单独做时缓存是热的（约 $0.08），它反而比原生 advisor 便宜。
- **对"强模型规划、worker 代笔"的结论**：在正确率上可行，但在这类几十到几百行的练习题上省不了钱。要省钱，需要输出远大于规划（比如几千行），并且规划那一步用不带运行框架开销的精简调用。

48 次运行合计 $8.818，包括无效的 Java 运行。另外，原生 advisor 的本地探测花了 $0.161。所有金额都按 SDK 的标价折算，不含 Daytona 费用。

## 更正：不带工具的精简调用（2026 年 10 月 16 日补测）

后来测量发现，前面各组的 Opus 会话因为挂着自定义 MCP 工具，每次都额外带了约 3 万 token 的上下文。Haiku 不带工具时只有约 640 token，带一个 MCP 工具时是 29,270 token。所以上文"Opus 写方案和直接做题花费一样"的结论，主要是被这笔开销带偏了。

于是在同样 10 道有效题上补测了两组，每题 1 次：

| 组别                                                                      | 通过      |   平均花费 |
| ------------------------------------------------------------------------- | --------- | ---------: |
| Opus 精简一次成型（不带工具，把题目和代码骨架放进提示，一次输出完整文件） | **10/10** | **$0.057** |
| 精简写方案、Haiku 代笔（Opus 不带工具写方案，Haiku 用 `bash` 实现）       | 10/10     |     $0.071 |
| 对照：Opus 单独做（带工具）                                               | 9/10      |     $0.239 |

- 去掉运行框架开销后，写方案确实便宜了：从约 $0.25 降到 $0.07。
- 但同样去掉开销的"Opus 精简一次成型"更便宜（$0.057），而且全对。在这类小题上，让 Opus 直接写代码，比先写方案再交给 Haiku 实现更省钱。
- 精简调用里偶尔仍会出现约 3 万 token 的上下文：在 Harbor 内运行的 20 次里有 5 次出现，本机复现时没有出现，原因未查明。平均花费因此略有偏高。
- 为排查这个问题，额外做了 2 次重跑和 2 次探测，不计入统计，但费用已记账。

## 查明并修复：约 3 万 token 的来源（2026 年 10 月 16 日）

上一节把这约 3 万 token 归因于"挂着自定义 MCP 工具"，这个判断不对。真正的来源如下。

**怎么查的：** 在本机起了一个临时服务，截获 CLI 实际发出的请求，并用假回复应答。这一步没有调用模型，费用为 0。

**原因：**

- **来源：** SDK 启动的 CLI 子进程沿用了桌面版会话的登录身份，于是自动加载了账号里的 claude.ai 连接器：Gmail 的 30 个工具和 Claude Docs 的 8 个工具，约 7 万字符，约 2.8 万 token。
  - `tools=[]` 只关掉内置工具，`setting_sources=[]` 只是不读本机的设置文件，两者都拦不住这些连接器。
- **为什么时有时无：** 连接器在后台异步加载。精简的单次调用能不能带上，取决于加载和发请求谁先完成，所以"20 次里 5 次"出现。
  - 多轮会话里，工具清单会在中途从 1 个变成 31 个、再变成 39 个。工具定义排在请求最前面，每变一次整段缓存就作废，要以 1 小时缓存的价格（输入价的 2 倍）重写。
  - 这就是 Opus 单独做的花费分成两档（约 $0.08 和约 $0.29）的原因。
- **附带问题：** 一次性调用也按 1 小时缓存写入，白付一倍输入价。
- **安全：** 检查了 155 份会话记录，模型没有调用过任何连接器工具。

**修复（`arms.py` 和 `launch.py`）：**

- 所有会话设置 `strict_mcp_config=True` 和 `ENABLE_CLAUDEAI_MCP_SERVERS=false`。
- 一次性调用设置 `DISABLE_PROMPT_CACHING=1`。
- Harbor 只拿到一份白名单环境变量。由于不再继承桌面会话的环境，CLI 会额外用会话模型调用一次来生成标题，因此同时设置了 `CLAUDE_CODE_DISABLE_TERMINAL_TITLE=1`。
- 思考设置原来就是默认的 adaptive、effort medium，现在改成在代码里显式写出。
- 修复后用截获服务确认：每轮请求只带 `mcp__task__bash` 一个工具；一次性调用不再写缓存；没有额外的标题调用。

**付费验证（每题 1 次，合计 $0.2015）：**

| 运行                                  |                  修复前 |  修复后 | 结果                 |
| ------------------------------------- | ----------------------: | ------: | -------------------- |
| Opus 单独做 cpp circular-buffer       |                 $0.3027 | $0.0665 | 两次都对             |
| Opus 单独做 go tree-building          |                 $0.2949 | $0.0537 | 两次都对             |
| Opus 单独做 python tree-building      | $0.0805（当时缓存命中） | $0.0567 | 两次都错，与之前一致 |
| Opus 精简一次成型 cpp circular-buffer |                 $0.2647 | $0.0246 | 两次都对             |

修复后，Opus 带工具单独做每题约 $0.05 到 $0.07，和精简一次成型的差距从约 4 倍缩小到约 2 倍。上文各组的花费都含有这笔开销，只能作为修复前的记录，不能直接拿来比较。
