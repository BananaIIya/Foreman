# GPT worker-first 验收与成本复测

修复后正式测试 **35/36 通过**，Luna 优先流程在这套小任务中共调用 Astra advisor **0 次**。正式组 API 等价成本 **$0.095585**，相较仓库中旧 B 组降低 **98.71%**。三项受控恢复测试全部通过，确认真实 GPT 调用能自动从失败或求助进入 advisor，再自动回到 worker，不等待人工审批。

本次使用现有 Codex 登录额度。美元采用旧报告冻结的标准 API 单价折算，**不是订阅实际扣款或账单**。A/B/C 对照来自之前的独立运行，并非本轮同时随机对照。

## 同题结果

| 执行方式                          |  通过 | 36 次总成本 | 耗时中位数 |
| --------------------------------- | ----: | ----------: | ---------: |
| 旧 A：Astra 独立执行              | 36/36 |   $7.194662 |   31.08 秒 |
| 旧 B：Astra 每题先规划 → Luna     | 36/36 |   $7.407491 |   44.73 秒 |
| 旧 C：Luna 独立执行               | 36/36 |   $0.091959 |   18.79 秒 |
| 新 B：Luna 先执行，失败才问 Astra | 35/36 |   $0.095585 |   17.49 秒 |

新 B 相比旧 A 降低 98.67%，相对旧 C 变化 3.94%。新 B 的报告协议、服务端独立检查、缓存与运行时段都有差别；小幅差异不应被解释成稳定的模型性能变化。旧报告及原始证据完整保留在 [GPT Astra/Luna 基线](../m4-gpt-2026-10-12/README.md)。

## 功能失败保留

B-emitter-2 的流水线和公开 smoke test 都显示完成，但独立隐藏测试失败：emit 开始后，第一个普通监听器注销第二个监听器时，当前快照仍应调用第二个；Luna 的实现用 active 标记跳过了它，得到 a 而不是 a,b。该边界要求原本已写在公开任务中。

这是一次真实的模型实现错误和验收覆盖盲区，不是评分器错误。本轮没有把隐藏反馈发送回模型，也没有重跑该案例来提升分数。worker 没有自报困难，公开检查又通过，所以 advisor 没有被触发。**当前机制只能根据已发现的失败升级，不能发现所有未测边界错误。** 与旧三组 36/36 相比，新组 35/36，不能声称质量完全不变。

## 自动恢复验收

| 场景           | 实际角色顺序                              | 结果 | API 等价成本 |
| -------------- | ----------------------------------------- | ---- | -----------: |
| failed-check   | Luna worker → Astra advisor → Luna worker | 通过 |    $0.038431 |
| legacy-pause   | Astra advisor → Luna worker               | 通过 |    $0.034482 |
| requested-help | Luna worker → Astra advisor → Luna worker | 通过 |    $0.133886 |

- failed-check：首次 worker 留下失败实现，提交可解析报告；服务端实际执行检查并确认 AssertionError 后自动升级。
- requested-help：首次 worker 主动给出 needs_advisor，核对升级原因包含 Worker requested advisor help。
- legacy-pause：显式带旧 pauseAfterPlan=true 的 plan-first 任务也自动交接，不产生 paused 状态。三个探针均未发送 resume 或批准命令。
- 三个 advisor 各运行一次且未调用工具；工作目录只改动 solution.mjs。测试代码未被修改，公开与隐藏检查均通过。
- 网页确认 GPT-6-Astra advisor、GPT-6-Luna worker、Acceptance checks passed，以及已移除计划审批开关；页面错误日志为空。截图保存在本机验收目录。原生手机端完成类型检查，本轮未做模拟器界面验收。

这些是人为触发的链路测试，只证明自动恢复机制正常，不代表 advisor 在真实难题上的救回率。

## 本轮发现并修复的问题

1. Codex 完成消息位于独立的子执行节点。旧读取条件只认 run 的根节点，误丢弃了有效 worker_result，导致成功任务也请求 advisor。现在按当前主 provider 对话选择完成消息，并排除子 agent 报告。回归测试使用真实结构的消息节点。
2. advisor 在 Files 中写出“文件名 — 说明”时，原解析器不接受。现在允许该说明，同时仍检查相对路径、重复路径和逐文件 Changes 章节。
3. 修复可选参数类型、Effect Path 服务注入和测试中的品牌类型标注。

发现问题后暂停了首轮矩阵；两次冷启动、四次正式任务与三个早期恢复探针的记录及费用全部保留在 diagnostic-attempt.json。两个在途正式任务带有主动中止标记。修复后在全新工作目录、线程和会话中重新跑全套；没有通过隐藏反馈调整题目、评分器或模型候选答案。

## 成本边界与账本

| 范围                         |  API 等价成本 |
| ---------------------------- | ------------: |
| 最终 36 次正式任务           |     $0.095585 |
| 最终两次 Luna 冷启动         |     $0.003014 |
| 最终三个自动恢复探针         |     $0.206798 |
| 首轮诊断、早期探针与中止任务 |     $0.997122 |
| 本次全部新模型调用合计       | **$1.302519** |

最终 38 个矩阵/冷启动任务对应 38 个原生会话；三个恢复探针对应 8 个原生会话。逐请求 native token、最终累计 token、T3 mainAgent 账本和费用独立重算一致，修正条目 0。

节省主要来自减少 advisor 调用频率。三个最终探针的单次 advisor 成本为 $0.035980、$0.031570、$0.130540，缓存会显著影响结果。即使已使用紧凑指令，Codex 原生宿主仍附加上下文；这些额外输入完整计入费用。当前 GPT advisor 没有产品级单次美元或输出 token 硬上限，限次也不是美元预算。基准脚本有采样式费用/超时停止保护，不能代替产品原生计费上限。
