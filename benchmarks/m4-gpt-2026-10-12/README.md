# M4 验收报告：GPT-6 Astra / Luna

2 次冷启动和 108 次正式运行全部完成，三组均为 **36/36 通过**。在这套小型 JavaScript 任务中，**Luna 单独执行的 API 等价成本最低、耗时中位数最短**。Astra→Luna 相对 Astra 单独执行贵 **2.96%**，通过率相同，耗时中位数长 **43.91%**，本轮没有观察到引入 advisor 的收益。

含冷启动合计 **$14.698483**，低于 $50 的实验预算。这里的美元是使用现有 Codex 登录额度运行后，按官方 API 标准单价折算的用量，**不是实际订阅扣款或账单**。

正式矩阵成本 $14.694112；两次 Luna 冷启动均通过，成本 $0.004371。Luna 单独组比 Astra 单独组低 **98.72%**。B 组的 Astra advisor 用量为 $7.303676，占该组 **98.60%**；Luna worker 为 $0.103815。36 个 B 流水线均为一次规划、一次执行，未触发 worker 重试或重新规划。

三组均满分，说明这套任务存在明显的满分上限。三次重复并不是三个独立任务，本结果不能证明 Luna 能在大型真实仓库中替代 Astra，也不能证明 advisor 在更复杂任务上没有价值。3% 左右的成本差异仅描述本次样本，没有统计显著性结论。

## 方法与计价范围

- 与前次 Claude 实验使用同一套 12 个 JavaScript 任务、3 次重复和轮换顺序，并发数 2。每次使用全新 Git 目录、T3 线程和原生 Codex 会话。B 包含 M3 的规划与公开验收流程，因此比较的是三种完整执行方式。
- 本轮推理开始前已冻结评分修订 2，包括之前 retry 异常子类勘误。运行中没有修改题目、评分器或候选答案，也没有根据隐藏测试失败重新调用模型。
- A 和 advisor 显式选择 Medium / Standard。M3 启动的 worker 可省略选项并使用原生默认值；原生记录逐个确认 Medium，且未发现非标准服务档位。实际模型均与冻结的角色分配一致。
- 隐藏测试通过独立、限时 Node 子进程运行，不向模型提供隐藏反馈。公开任务限制模型只修改 solution.mjs；这不是针对恶意模型的隔离沙箱。
- 本轮账本范围为 Codex 记录的 mainAgent token。此前 Claude 报告的完整会话成本包含 CLI 辅助调用，两份报告的总成本范围不同，不宜直接作为模型价格对比。
- 定价来自 [OpenAI 官方价格页](https://developers.openai.com/api/docs/pricing)、[Astra 模型页](https://developers.openai.com/api/docs/models/gpt-6-astra) 与 [Luna 模型页](https://developers.openai.com/api/docs/models/gpt-6-luna)，核对日期 2026-10-13 UTC。每百万 token 的 Astra 输入 / 缓存读取 / 缓存写入 / 输出为 $10 / $1 / $12.50 / $50，Luna 为 $0.10 / $0.01 / $0.125 / $0.50。推理 token 已含在输出中，不重复计费。
- 逐请求重算价格，最大单次输入 24,403 token，未触发超过 272,000 token 的长上下文附加倍率。缓存命中、服务负载和小样本会影响成本及耗时。
- 未调用 NVIDIA / Nebius。本轮结果不替代原计划中对 Nemotron 的专项验证。

实验时间：2026-10-13T02:34:33.098Z 至 2026-10-13T03:08:49.819Z（UTC；Chicago 为 10 月 12 日晚）。T3 服务基线为 178d849944402dd82db49e5dc6cf94d61d2750f2，Codex CLI 0.162.0-alpha.17.2，Node 24.21.0。命令使用新增的 --profile gpt；默认 Claude 协议保持兼容。
